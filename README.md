# prosemirror-beltype

BelType's fragmentainer for [prosemirror-fragview](https://codeberg.org/egildo/prosemirror-fragview): Cicero's page implementing `fill` over the engine's own objects, with every gap between a one-round host and an editor's view filled the ProseMirror way. The engine is not changed to do this and never learns ProseMirror's name; the view never learns the engine's. This package imports both.

Install and try it: `npm install` takes the engine from npm (`@beltype/cicero`) and the fragmented view from Codeberg at a pinned commit, so a clone needs nothing else on disk. An editor built on it lives in its own repository, [prosemirror-beltype-venue](https://gitlab.com/aicof-design-team/prosemirror-beltype-venue): a six-page pagination specimen whose pages are cut as you type, installed from what is published. The specimen harness (`npm run specimen`) needs no other checkout either: it serves the finished fixtures under `fixtures/` itself, with the engine's head spliced in, and parses with `prosemirror-fragview/schema-generic`; `FRAGVIEW` names a fragview checkout to run against instead of the pin.

The plan and its phases are in [docs/plan.md](docs/plan.md). The rule it builds under is BelType's decision record [*the engine knows no view*](https://github.com/egildo/beltype/blob/main/.claude/decisions/project/the-engine-knows-no-view.md).

Phase 1, the page as fragmentainer without reads, is built on its branch: `CiceroPage` fills one turn of the engine's build loop through the engine's own functions, and `ciceroContainers` hands the view a page per entry from the geometry table. Measured in BelType's own page against the CLI's round, the specimen's 9 pages and a 26-page fixture that reaches the Stonehand (8 Class B cuts, 13 Class A) agree page for page, first and last word, with no warning on either side; the showcase's first difference is its second page, where the engine repeats a table's header and this package does not yet. The phase found that a slice cannot be its own source in the engine's measure context (the Stonehand reads a second rendering outside it), that the view's editing host passes its text mechanics into a page, and that the renderer's `adjoin` is wrong after a forced break; [docs/results.md](docs/results.md) has the record and what is not done.

## Hosting the pages

Mount the view with `containers: ciceroContainers(document)` and `handleFillRejected`, both exported here. A page whose fill throws already answers past the node at its start, unmeasured, with `failed` in its account; `handleFillRejected` is for a fill whose safety net throws too, which the view would otherwise leave dirty, so every page after it would wait. With it the page is shown empty, answers past the node, and `chain.settled(doc)` answers incomplete naming the page, so a host that prints must refuse while it is so.

Keep the content CSS document-level. Cicero measures every page in its own container at the end of `body`, outside the view's element, and the chain's rendering of the whole state sits outside it too, so a rule scoped under the host (`.ProseMirror p`, `#editor table`) dresses what the reader sees and not what was cut. At its first fill the factory reads the document's sheets once and warns on the console for every such selector, naming it, ten at most and then a count; a rule on the host itself, and one on a highlight such as `::selection`, passes. The root carries no `ProseMirror` class unless the host gives it one.

Prefix the ids in the author's content, or keep the host app's own ids out of the document the pages stand in. Cicero 0.1.6 resolves a `target-text()` reference by id across the whole document, so an author's `#intro` can read the text of a host app's element of the same id and print it on the page and into the PDF.

The view's `window: { build: 'near' }` is not supported with Cicero pages: the chain stays incomplete there, and the engine's reads loop takes a partial chain for a whole one. Use the default window.

Late truth, a size or element that arrives after a fill, is heard through the page's own `ResizeObserver` over its top-level nodes, not through the engine's rim (`watchLateTruth` in Cicero's `seam/rim`), which no public export of `@beltype/cicero` reaches yet, 0.1.9 included. The fragmented view refills the page that moved and the page before it, whose cut may have read the content that moved.

A page waits for the fonts and its images for at most four seconds (`WAIT_MS`, read through `CiceroPage.waitMs`). A page whose wait ran out is measured with what it has, says so once with a `console.warn` naming the page and what it lacked, carries `provisional: true` in its account, and is filled again when the fonts are ready or the first missing image loads or fails; that fill clears it. A host that prints must not print a provisional page.

A PDF embed whose fallback `<img>` has no `alt` is warned of in the editor, by its `data`, and drawn with no alternative text, so the pages still fill and Caster refuses the figure at print. This needs the Cicero release whose facsimile `install` takes `missingAlt: 'warn'`; Cicero 0.1.9, the pinned one, refuses at intake, and every page the embed's document reaches fails.

`collapsedSpaces()` is a trade: it writes U+00A0 into the model wherever a typed space would collapse, as the platform's own contenteditable does in its DOM, so the saved document holds non-breaking spaces where the author typed plain ones. A host that wants a clean model leaves the plugin out and accepts that a double space, or a space at a line's edge, collapses on the page as it does in print.

## Browsers

Desktop browsers of the Chromium family are the measured target: the CLI round, the guard and every suite here run Chromium. Elsewhere the view loads and edits, but it is not WYSIWYG, since the pages are laid out by another engine than the one the measurements were taken in, and nothing measures the difference; Caster, the printer, refuses outside Chromium as it already does. Android is unsupported for now: a host on Android should mount a plain `EditorView` from `prosemirror-view` over the same state, without the pages.
