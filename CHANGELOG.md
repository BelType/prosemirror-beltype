- A settle clears the engine's timing entries (*the run keeps time*, amended 2026-11-08: the long-lived host clears what it has read). Cicero writes a `cicero:` measure per phase and never clears, and the browser keeps every entry for the page's life, so a long session accumulated them without limit. At the end of each settle that is still the view's, `Chain` totals the `cicero:` measures by name onto the settle's record (`measures`), then clears them and the `cicero:` marks; an overtaken settle clears nothing, and a realm without `performance.clearMeasures` is left alone. The harness's keystroke reading takes `cicero:reads` from the record. `test/settle.test.js` has the case, red before the change.
Egildo's ruling of 2026-11-08: the intake warns, and the waits time out.

- `takeFacsimile` passes `missingAlt: 'warn'` to Cicero's facsimile `install`, so a PDF embed with no fallback `alt` is warned of by its `data` and copied with no `aria-label`, and the pages fill; Caster refuses it at print. Cicero 0.1.9 ignored the option and refused as before; the pin now names 0.1.10. `test/facsimile.test.js` checks it under a Cicero that knows the option and skips under one that does not.

## 0.1.2 (2026-11-08)

prosemirror-fragview 0.1.2 (2026-11-08).

- The `prosemirror-fragview` dev pin moves from the git commit `c715783` to `0.1.2` on npm, and the peer range from `*` to `^0.1.2`: block node views, the paced ripple, the one-step delete and the browser scope. `test/block-faces.test.js` runs green without `FRAGVIEW`. 88 of 88 serially against the pin.

Content CSS is document-level (ruled 2026-11-08).

- At its first fill the factory reads the document's sheets once, `@media`, `@layer`, `@supports` and `@import` bodies included and a cross-origin sheet skipped, and warns on the console for every selector that scopes a content element under the view's element (`warnScopedRules`, `src/scoped-css.js`): a descendant or child combinator whose left part matches the host and not a bare `div` at the end of `body`, where the engine's measure stands. The warning names the selector and says the rule does not reach the measure; ten are named, then one line counts the rest. A rule on the host itself, a document-level rule, one scoped under another element and one on a highlight pseudo-element pass. A combinator inside `:is()` or `:where()` is not parsed. `test/scoped-css.test.js` has the cases, red before the change.

The view's paced ripple (prosemirror-fragview's `fix/ripple-yields`, 2026-11-08).

- `settled()` waits while the view is `rippling`. The fragmented view now fills the pages in view and one more before the next paint and the rest in idle slices, so between two slices it holds a dirty entry with no fill in flight, which `Chain.check` took for a chain stopped short: the reads loop settled over the first pages, delivered their reads, and never read again when the slices filled the rest, so the contents' page numbers were those of the half-filled chain (seed 6 of `test/random.test.js` against fragview main: pages 1, 2 and 5 read 5 where the cold fill reads 7). A view with no `rippling`, the pinned one among them, reads as one that never pauses. `test/chain.test.js` has the case, red before the change.

Block node views on the page (2026-11-08, the record `a-block-with-no-content-hole-is-a-face-where-it-stands-whole`).

- `test/block-faces.test.js` proves fragview's block faces under `CiceroPage`, with a node view for a `<table>` that has no content hole and draws the same table from the node. A table that fits gets its face, keeps the same element through a refill, a move to the next page whole and a move back to the page before, and the arrows step over it. A table the page divides keeps `toDOM`'s drawing on each page and its view is never made. `break-inside: avoid` moves a straddling faced table whole, and a tall one divides all the same. A tall leaf sliced as a painted shell has one face, on its first page. In every case the chain is the one the same document has with no node view, and a divided table under the wrapper is pinned to its tracks and laid out as the bare one, piece by piece. Until the fragview pin moves, the file runs against a checkout of fragview's `fix/block-faces` named by `FRAGVIEW` (its header says how); against the pinned fragview the table's view is refused. Nothing the page does changes: its header now names the block wrapper as a mapped element like any other.

Browser scope and `collapsedSpaces`, by the rulings of 2026-11-07.

- The README says which browsers are measured: desktop browsers of the Chromium family. Elsewhere the view loads and edits but is not WYSIWYG, and the printer refuses as it already does. Android is unsupported for now, and a host there should mount a plain `EditorView`.
- The README states `collapsedSpaces()`'s trade: it writes U+00A0 into the model where a typed space would collapse, as the platform's own contenteditable does, so a host that wants a clean model leaves the plugin out and accepts the collapse.

Cicero 0.1.9 (2026-11-07).

- The Cicero dev pin moves from 0.1.6 to 0.1.9. Two fills of one document in flight no longer share the engine's measure container, so the overtaken case on the flow fixture, which gave 42 wrong answers over 25 pairs, gives none, and the random edits that failed on nearly every fixture pass. Clear `node_modules/.vite` after the pin moves, or Vite keeps serving the old copy.
- `wrapResumed` (`src/shells.js`) takes `WRAPPED` and `clonesDecoration` from Cicero's fragmentation face, where it spelled the word and read `box-decoration-break` itself. The peer range rises to `^0.1.9`, the first release that exports them. Nothing a page draws changes.
- The harness's overtaken case counts the law holders left standing once the chain is quiet, not while a refill of the view's own is still in flight, which it used to report as one left behind.
An atom taller than the page area is sliced as a painted shell (2026-11-07, `css-fidelity-atoms-and-monoliths`; the ruling is the decision record `a-tall-atom-is-a-painted-shell`).

- A node with no editable inside (an image, a rule, an embed) whose drawing is taller than the page area is now cut at the page's edge and continued painted on the pages after it, as the engine already slices a monolith. It used to be taken whole when the engine's cut fell inside its drawing, for example on an image inside an atom drawn as a figure: the page clipped it, its lower part showed on no page, and only a console line said so. Such a page's account now says `E`, `next.shell` carries the painted remainder, and the page after begins in it. `test/tall-atom.test.js` proves it on a 700 px image inside a figure atom on a 260 px page area, three pages that show 0 to 260, 260 to 520 and 520 to 700 px of it and agree with a fresh fill; it is red before the change.
- `whole` stays for the true leftover: a cut that maps to no position and that the painted shell cannot take, such as an inline atom or a block that is not an atom. That case keeps its warning.
- `fixtures/tall-atom` adds an image alone in its paragraph (the form a Markdown image takes) and a block `<object>` embed, both taller than the page, to the harness. Under the generic schema the engine's own cut already reaches both, so the fixture guards that they still agree with the CLI page for page.
A chapter named by `:has()` keeps its page name on a page that divides it (2026-11-07, `pmb-random-edit-page-name`).

- A page whose slice divides a top-level box named through a rewritten `:has()`, such as the specimen's `section:has(> h1) { page: chapter }`, now reads the box's page name, its `break-before` and every other rule of that selector as the cold fill does. The slice renderer writes `fragment` on the root of every divided piece, and Cicero's has-words rewrite gives such a root only its `has:` words, which nothing wrote here, so the root fell back to `page: auto`. The originals now answer each top-level node's `has:` words from its original (`hasWordsOf`, the engine's `askBox`), and every slice a page renders gets them on its divided root: the trial, the law copy and the shown page.
- Found by the random edits (seed 6, six edits): a page refilled with its last span bounded its trial inside the chapter, read the chapter as unnamed and was cut in two for a page name, so the table of contents gave page 6 for page 5. The same reading hit any page that resumes a top-level named chapter. `test/random.test.js` holds the run as a real test now.

A page that shows the rest of a table row or a flex row (2026-11-07, `incremental-correctness-4`).

- A same-length replacement or a mark in the rest of a row item that is not the last one now reaches the page that shows it. That text's positions lie inside the page before, which the cut through the row ends at the last item's place, so the edit refilled only the page before; its cut and its hint stayed the same, and the page after kept the old text. A `CiceroPage` now answers `shows` from its fill: from the lowest place of the row items it resumes, where that is below its start, to the end its own slice was rendered to, where that is past its cut (a painted shell, a row's end). The fragmented view dirties a page whose `shows` an edit touches.
- A caret in such a rest is drawn on the page that shows it. A page holding a row's pieces answers `pointAt` with null for a position between its pieces that it does not render, where it used to answer the nearest point, and finds a resumed item's rest below its own start in the item's own element; the view then gives the position to the page whose `shows` holds it. `test/shows.test.js` proves both on a flex row whose first column runs over five pages, red before the change.
- This needs the fragmented view's `shows`, which `prosemirror-fragview` has from `c715783`; the dev pin names that commit. With an older view the answer is ignored, and the caret and the stale page stay as they were.
- Still open: the top of a painted shell. The page after a painted cut holds the whole box, the part already shown pulled above its clip, so its `pointAt` answers for that part and a caret there still lands on the page after. Telling them apart needs the page's geometry in `pointAt`.

The measurement stands on its own.

- `scripts/specimen.mjs` no longer starts a BelType checkout's dev server. It serves a finished document's folder itself, with the engine's head spliced in as `beltype print` does, and asks the engine for its whole run. `BELTYPE_ROOT` and `BELTYPE_STUDIO` are gone.
- The fixtures are finished HTML, `fixtures/<name>/index.html`, on `fixtures/base.css` and `fixtures/fonts`, which freeze what the old command line put under a document. The specimen is `fixtures/specimen`, and it is the default target. A target is now a folder, so `@beltype/specimens`' documents can be measured too.
- The harness parses with `prosemirror-fragview/schema-generic`, and the pin moves to fragview's `main` for it. `FRAGVIEW` names a checkout to run against instead, for a change not yet pushed.
- A leaf's node view is proved on a real `CiceroPage` (`test/faces.test.js`): the same cuts, and the host's element kept across a refill and a move to the next page. Nothing in the page changed for it.
- A first fill, a restored state and an `invalidate()` settle cold, as the engine's driver settles anything but a resume, so the editor lands on the page numbers a reopen and the command line land on. Only an incremental settle starts from the Ledger's tables, a settle that ended incomplete no longer writes them, and `invalidate()` blanks the page total until a page runs to the end again (`test/settle.test.js`).

- `CiceroPage` answers `reach`, how far its decision read: every box that can stand on the page, the first textblock of the first in-flow box that cannot, and the whole of a table, flex or grid container it stands in. With `prosemirror-fragview` after 0.1.1, a change in the tail of a divided paragraph now refills the page before it. With an older view the answer is ignored.
- A hint carries its shell and row positions relative to the cut, so a page no longer drops a hint because an earlier edit shifted the document. With `prosemirror-fragview` after 0.1.1, a hint that changes under an equal `to` also fills the next page.
- `collapsedSpaces` no longer binds words: spaces typed one by one at a line's end, then a word, alternate as the same run inserted at once does. They used to stay as two U+00A0 in the saved document.
- A fill that throws no longer stops the chain. The page shows the node at its start unmeasured and answers past it, its account says `failed`, and `chain.settled(doc)` answers incomplete until the page fills.
- A fill whose rendering throws, a node's `toDOM`, no longer stops the chain at that page: the safety net rendered again outside any guard, so `chain.settled(doc)` never answered. The page now shows empty and answers past the node, and the chain hears of the failure whatever the safety net does. The harness gains the edit `throw-render`.
- A page says what its foot cuts off with no later page to show it: `clipped` in its account, in pixels of the flow and of a parallel flow, and one warning per page.
- A bounded feed that decides nothing takes the node at the page's start whole, with a warning, where it used to take the rest of the document and close the chain.
- The running copies in the margin boxes are `inert`, not editable and not spellchecked.
- The Ledger follows the chain when `setProps` gives the view a new factory.
- `Chain.settles` and `Originals.timings` keep the last 64 records, the settle record holds no document, and the per-state element count is gone.
- Changing the page's geometry under a mounted view is proved and documented: link the sheet with the new `@page` and give the view a new factory, `view.setProps({ containers: ciceroContainers(document) })`. On the new fixture `repage`, whose second sheet also sets margins by side, the repaged chain equals a fresh mount and the CLI's pages of the same geometry (`repage-b`) on every page. `view.invalidate()` on the same factory keeps the old geometry, since the factory reads the geometry table once. The harness gains the edit `repage:<sheet>`.
- The chain is cut again when the device pixel ratio changes, as a browser zoom or a move to another screen changes it: a `resolution` media query, asked again at each new ratio, calls the view's `invalidate()` once the ratio has held for 250 ms. A page cut at a ratio other than 1 says so with `dpr` in its account, and the console says it once per document and ratio, since print runs at 1. `scripts/specimen.mjs` gains `--dpr n`.
- A page under a zoom built on a CSS transform no longer dispatches `moved` at every frame. It recorded each node's height after the transform and compared it with the observer's `borderBoxSize`, from before it, so at `scale(0.5)` the four pages of a test document dispatched 120 `moved` in 30 frames after the chain settled. It now takes the observer's first report after the fill as the height to compare with (`test/zoom.test.js`, at 0.5 and 1.5).
- A page ends the boxes an ordinary cut divides as the engine ends its constructed first fragment, through `mutateToFirstFragment`: the last line before the cut stays justified, a box with `box-decoration-break: clone` keeps its block-end border and padding, and the innermost divided box takes the extension as block-end padding, so its background reaches the page's foot. The trial does the same at its bound, and a box the page resumes keeps its cloned block-start border and padding, on the trial and on the page. The new fixture `justified` was 10 pages against 10 with the first difference on page 4; it now agrees on every page and every divided piece's edge. The harness now also exits with an error when the cut-off pieces' edges differ.
- `scripts/specimen.mjs` exits with an error when the view's pages and the CLI's hold different words on any page (the guard, `compareHosts`), where it used to print the difference and exit 0. Two differences are allowed, each named in the script's `ALLOWED` list with its fixture, its page and its reason: `multicol` page 3 and `clipped` page 3.
- The harness gains the edits `throw`, `tail`, `past`, `beyond` and `carried`, and the fixture `clipped`, and `scripts/specimen.mjs` gains `--strict`, which exits with an error when an edited chain differs from a fresh fill.
- A host can now see what a page cuts off. `chain.settled(doc)` answers `clipped`, a list of `{ page, flow, parallel }`, one for every page whose account has `clipped`, and leaves it out when no page clips; it does not make the chain incomplete. A page that begins or ends in a shell or a row used to be skipped; it is now asked about its parallel flow (a float or an absolutely positioned box), though not about its flow. A float that starts on the page but stands wholly below the cut is now counted too, where only one crossing the cut was. The tail is still lost on screen, while the CLI carries it to the next page: carrying it (the engine's `adjudicateFlow` exported, and a carried range in the hint) is still owed. `test/clipped.test.js` has the two cases, a page that begins in the flow and one that begins in a shell.

- The `prosemirror-fragview` dev pin moves to `805db68`, its `main` with the hint passed on every fill, `handleFillRejected`, the selected node's class on every piece and every `handleDOMEvents` key. Nothing in this package changed for it: `pnpm test` 67 of 67, and every fixture agrees with the CLI and with a fresh fill under `--strict` with the edits `start;key:2;delete:2;end;paste`.
- A page reads its hint from `fill`'s fourth argument, which `prosemirror-fragview` 805db68 hands every fill, and `Chain.hintFor`, the side channel that read it by index, is gone. On the chrome fixture, retitling `Folios` gives 17 of 17 pages equal to a fresh fill, and 5 of 17 when the page ignores the hint it is handed. A view older than 805db68 refills a page under the hint it was built with.

- `handleFillRejected`, exported, is the view's prop for a chain of Cicero pages, as `prosemirror-fragview` 805db68 defines it. Any other container is left to the view.
- The README says how to host the pages: the two props, prefixing author ids so Cicero's `target-text()` cannot read a host app's element of the same id, and that the `near` window is not supported with Cicero pages.
- Late truth stays on the page's own `ResizeObserver`. `@beltype/cicero` 0.1.8 has `watchLateTruth` in `dist/seam/rim.js`, used by its client, but no export reaches it: `./internal/*` maps `dist/src` only. Seating it in `ciceroContainers` needs Cicero to export it, for instance a `./rim` entry for `dist/seam/rim.js` with `watchLateTruth`, `bringsNewFace` and `knowLoadedFaces`, and the page to answer its `presented`, `pageHolding` and `measured` questions from the chain's pages. The Cicero dev pin stays at 0.1.6.
- The harness makes random edits: `node scripts/specimen.mjs <fixture> --random seed:n[:runs]` makes `n` edits from each seed, aimed at the cuts (a page's `from` and `to`, a textblock inside a shell or a row item, not the last first), with typing, deletes, Enter, joins, `setNodeMarkup` on headings, a wrap in a blockquote, a lift, undo, redo and `redraw`. It waits for no fill between two edits, so an edit can land on a page being filled, and compares the whole run once, at its end, with the cold fill after `invalidate()`; it exits with an error naming each seed that failed. Every run starts from the document as mounted, so a seed replays alone. `--paced` waits for quiet after every edit, so a fault that needs no fill between two edits can be told apart, and `--skip i,j` draws those edits without making them, to narrow a seed down. It is not in `pnpm test`.
- The random edits found two faults (docs/found.md). Under both, the specimen's seed 6 leaves a page cut for a page name the cold fill does not see, after a chapter heading is split and lifted out of its section; it is a `todo` case in `test/random.test.js`, not fixed.
